## TL;DR

- All three M0 workflows now run through the runner, pass their checks and have a manifest
  (K4). Re-running each from its manifest alone gave identical output: same pixels, same splat.
  - The three: Wan VACE (video), BiRefNet background removal (image) and TripoSplat
    image→3D splat (local 3D).
- First real silent failure on this Mac. TripoSplat's preview render reported success and saved
  a fully black video; our checks rejected it.
- ComfyUI was upgraded to 0.38.2 (templates 0.11.74) through Comfy Desktop on Oct 5, so the
  0.35 pin is gone. Wan still passes on 0.38.2 (5/5 runs, \~48 s each).
- Research: LTX-2.5 "Layout to Render" (1–2 Oct) turns a blocky 3D playblast plus a styled first
  frame into a finished shot. It is the closest ready-made match to the Unity idea so far.

## Research: what's new

- LTX Layout to Render: open, but the weights are gated, it needs the LTX custom nodes, it's
  22B, and LTX on Mac has the known black-output bug
- ComfyUI 0.39.0 (5 Oct) adds `--offline` and `--disable-partner-nodes` (useful for unattended
  safety) and raises SaveVideo quality to CRF 18, so our file-size checks need a new baseline
  after upgrading.
- comfy-cli 1.22.0 likely fixes the "value lands in the wrong field" bug (PR #935). It is marked
  unconfirmed in the wiki.
- MiniMax H3: running it locally in the US/EU/UK/KR needs a paid commercial licence (from
  $5k/month). That resolves last run's open question.

## Implementation progress

- Lab note: [Experiment 004](../../experiments/2026-10-06-m0-three-workflows-k4-manifest/)
- `comfy build init` works locally without sign-in (8 s). It hashes every model and records
  the pip freeze. It is now the environment lock in `scripts/demo-manifest.py`.
- File bytes never match between identical runs, because ComfyUI embeds the prompt in the file
  metadata. Manifests therefore compare content hashes instead.
- BiRefNet on a Unity frame: the cutout matches Unity's own segmentation pass at IoU 0.972. This
  is our first adherence check scored against Unity ground truth.
- TripoSplat: the .spz splat itself is valid (262k points; a point preview shows the input
  drawing). Only the orbit-preview video is broken on MPS. Workflow #3 therefore saves the .spz
  only, checked by the new `scripts/spz-check.py`.
- Runner: 13/13 tests. New this run:
  - Stall timeout: cancels a job that sends no progress events.
  - Pre-flight: a missing model or node is refused before anything is queued.
  - Real `kill -9` of ComfyUI mid-job: the job is classed "lost" and the retry passes with
    exactly one output.
  - TripoSplat crashes (after it had saved a partial file): marked `unknown-outcome` and not
    resubmitted blindly.
- Unity itself wasn't run this time; all Unity inputs came from existing captures.
- Not done for M0: adherence checks for Wan and TripoSplat, the E2 comparison against the
  browser's "Save (API)", and a real model download for P1 (every model was already on disk).

## Risks / blocked

- Cause of the TripoSplat failure: on torch 2.12.1 / MPS, batched `linalg.inv` returns zeros
  above \~65k matrices and aborts at 262k (the template default). Any node doing large batched
  inverses is exposed. Not reported upstream: runs don't post.
- There is no adherence check for Wan yet; V1 alone can't catch plausible-but-wrong output.
