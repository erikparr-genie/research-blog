## TL;DR

- M1 has begun. The first batch of 11 shipped templates ran unattended: model download, E2
  conversion check, runner, then validation. 10 of 11 run on MPS. The one real failure is MoGe-3
  (fp16 op missing on MPS).
- New E2 finding, with a measured impact: comfy-cli fills in a default 512×512 `bboxes` box that
  the browser never sends, and that stops SDPose from detecting anyone (49 vs 4,615 skeleton
  pixels). The batch tool now strips such defaults automatically.
- VACE strength matrix (3 styles × 0.50–0.75): adherence holds from 0.55 up for every prompt.
  The M0 prompt breaks at 0.50.
- Wan ran 1.6× slower when other models were still loaded in memory (80 s vs 49 s). The runner now
  has a `free_before` option. Torch 2.15 is not final yet; release is scheduled for tomorrow, 28 Oct.

## Research: what's new

- ComfyUI 0.43.0 (27 Oct) adds an opt-in local agent (`--enable-agent`) and has no Mac fixes. It's
  now our upgrade target.
- LTX black frames on Mac: still open (#15804/#15818). Fix PR #15819 is unmerged.
- comfyci-runpod-worker is Comfy-Org's GPU regression testing behind ci.comfy.org. It keeps
  reference outputs per environment and sets thresholds at 3× the measured re-run noise. That's a
  good pattern for our validator at the upgrade point.
- Also new: two papers, WorldForge V2 (camera paths without retraining) and VibeVideoBench (video
  evaluation). No news from comfy-cli, comfy-sdk, comfy-mcp, Wan/VACE or ltx-2-mlx.

## Implementation progress

- New `scripts/m1-batch.py`, which runs, for each template:
  - comfy-cli conversion;
  - the headless-frontend diff (E2) with rule checks;
  - input rewiring to Unity captures (the template sample inputs aren't installed);
  - sha256-checked model downloads.
- Batch 01: 8 models downloaded (15.9 GB). The batch then ran in about 2 min.
  - Passed: DA3 image/video, MoGe-2 depth and mesh, Lotus depth, SAM 3.1, BiRefNet, SDXL Turbo.
    Every utility template took under 32 s.
  - Failed or rejected:
    - MoGe-3: `"compute_index_ranges_weights" not implemented for 'Half'`.
    - SDPose: the bbox bug above; it works without the box.
    - FILM interpolation: a validator false positive. The frozen check uses a fixed threshold, so
      doubling the frame rate fails it.
  - Lab note: [Experiment 009](../../experiments/2026-10-27-m1-batch-01-small-templates/)
- K1 matrix: 18 Wan clips, all scored. Depth MAE is 0.022–0.048 from 0.55 up. At 0.50, the M0
  prompt scores 0.126: the figure becomes a woman standing facing the camera.
  - Lab note: [Experiment 010](../../experiments/2026-10-27-k1-vace-strength-matrix/)
- Runner: `free_before` POSTs `/free` before a job. Warm Wan went back from 79.8 s to 48.9–49.6 s
  after `/free`. Runner tests pass.
- Unity wasn't run; all inputs came from existing captures.

## Risks / blocked

- K1 used one seed per cell, so the 0.50/0.55 step is not a rule yet.
- Adherence is still blind to small placement and scale changes.
- The validator's frozen check needs to account for fps before interpolation or upscale templates
  enter the catalog.
